04连接序列与探针选择

采集启动 = FUN_14003ef60（"ReadStart" 的第一步）。它串起「加载 DLL → 选探针 → 开探针 → 配器件 → 连目标 → 探测 HSS 能力」六步； 任一步失败都会写一条 ERROR 日志（FUN_14003f110 → "ERROR: %s"）并中止； 该日志在作业段结束时汇总为一次模态消息框（见 §15.5 的分段日志机制）。

FUN_1400418f0（选探针 + 打开）→ FUN_1400419f0（配器件 + 连接 + 能力探测）

// ① 加载库（FUN_140028ec0 内部按顺序 LoadLibraryA）
if (!JLINK_LoadLibrary())  return err("Failed to load J-Link library.");

// ② 选探针：连接类型 config+0x5AC
switch (connType) {
  case 2:  // TCP/IP
      if (JLINKARM_SelectIP(config+0x490 /*IP 串*/, 0) != 0) err("Failed to select J-Link via IP ('%s').");
      break;
  case 0:  // USB —— 优先昵称
      if (config+0x510 /*nickname*/[0])
          if (JLINK_EMU_SelectByUSBNickname(config+0x510) < 0) err("Failed to select J-Link with nickname ('%s') via USB.");
      break;
  default: // USB —— 按序列号
      if (JLINKARM_EMU_SelectByUSBSN() < 0) err("Failed to select J-Link with serial number ('%d') via USB.");
}
if (JLINKARM_OpenEx(0, 0) != 0)  return err("Failed to connect to J-Link: %s");

// ③ 器件（config+0x00 起 128 B）：空/未知名 → 弹出 DLL 自带的器件选择框
if (device[0] == 0 || !lookupDevice(device)) {
    idx = JLINKARM_DEVICE_SelectDialog(hMainWnd, 0, 0);
    if (idx == -1) return err("User cancelled device selection.");
    struct DevInfo info;  info.size = 0x978;
    JLINKARM_DEVICE_GetInfo(idx, &info);      // 0x978 B，前 0x80 B 为器件名等字符串
    /* 把 info 的字符串字段逐 8 字节搬进 config+0x00..0x7C，再 FUN_14004ec40 刷新派生字段 */
}
JLINKARM_ExecCommand("device = %s", device);     // 失败 → "Failed to select target device '%s'."
if (config+0x38C /*ScriptFile*/[0])
    JLINKARM_ExecCommand("ScriptFile = %s", ...); // 失败 → "Failed to select script file '%s'."

// ④ 接口与速度
JLINKARM_TIF_Select(config+0x59C);               // 0=JTAG, 1=SWD, 7=?（JTAG 变体）
JLINKARM_SetSpeed(config+0x5A0);                 // kHz
if (rttSearchRanges[0]) {
    rc = JLINK_ExecCommand(rttSearchRanges, 0, 0);   // "SetRTTSearchRanges ..." 由 -RTTSearchRanges 生成
    if (rc != 0) return err("Wrong syntax for \"-RTTSearchRange\".\n");
}
if (JLINKARM_Connect() < 0)  return err("Failed to establish connection to target.");

4.1 HSS 能力探测：只影响一个"写了不读"的全局

if (config+0x5A4 == HSS) {                       // 仅 HSS 模式探测
    if (JLINKARM_EMU_HasCapEx(0x35) == 0) {        // 0x35 = HSS 能力位（EMU 能力扩展）
        samplingPeriod = 20000;                     // 无 HSS 能力 → 回退 20 ms 轮询
    } else if (JLINKARM_GetDLLVersion() > 0xC79B) {
        struct { uint32_t f0, f1; } caps;          // 8 字节 caps
        if (JLINK_HSS_GetCaps(&caps) == 0)
            DAT_14285da90 = 1000000 / caps.f1;      // ★ 全局只写不读（见 §6.4）
    } else {
        samplingPeriod = 10;                        // 老 DLL → 固定 10 µs
    }
}
项值 / 含义等级
JLINKARM_EMU_HasCapEx(0x35)能力位 0x35 = 53 → HSS 支持。JLink_x64.dll 中存在对应能力分支（字符串 "Current setup does not support background memory access mode" 即其后端失败路径）观测
DLL 版本门槛 0xC79B= 51099。JLINKARM_GetDLLVersion() 的十进制编码（%d.%.2d 打印），即要求 DLL ≥ V5.10.99 才调用 JLINK_HSS_GetCaps推断
caps.f1 单位反编译为 TimeResUs = 1000000 / caps.f1 → f1 是 Hz（时间戳频率），1e6/Hz = µs/tick。因该全局只写不读，实际不影响采样推断
回退周期无 HSS → 20 ms；老 DLL → 10 µs（按 FUN_14003f400 写入配置 +0x5A8 采样周期）观测

4.2 前置命令与"会话模式"

JLINKARM_ConfigJTAG(config+0x5B4)仅当 TIF ∈ {0(JTAG), 7} 且 config+0x5B0（JTAG_IRPre 原始值）≥ 0 —— 真正下发给 DLL 的是 +0x5B4（IRPre），+0x5B0 是 DRPre
JLINKARM_ExecCommand("SetSkipInitECCRAMOnConnect = 1")每次连接前固定下发，跳过 ECC RAM 初始化（对无 ECC 的目标加速连接）
SuppressGUI = 1 / 0命令行解析期间抑制 DLL 弹窗（FUN_140041cd0 前后包夹）
会话模式 config+0x5B8由文件结构的 Connection == 4 置位；停止采集时若该位为 1 则不下发 JLINK_HSS_Stop —— 即"寄生"在别人的调试会话上，不夺走探针的控制权
