18对 OpenScope 的启示

本节只保留可执行的结论：每条都指明"抄什么/不抄什么/为什么"，并给出对应的证据位置。 前置背景：OpenScope 是 C11 主线、多实例（net_drive 三实例）、网络采集与远端回放是核心场景。

18.1 三条最有价值的结论

① HSS 是"真 µs 采样"的现成答案，且不需要目标端配合。 JLINK_HSS_Start(描述符数组, n, 周期µs, 1) + 10 ms 周期的 JLINK_HSS_Read 到 ~2 MB 缓冲。 探针自主采样并缓存，采样率与主机轮询彻底解耦；描述符只有 {addr,size}， 所以目标端不需要跑任何采样代码（走 AHB-AP 后台访问，不占 DWT/SWO）。 对 OpenScope 的"µs 级 + 不打扰目标"需求，这是唯一不需要改固件的路径。

② 采集后端只产出"带时间戳的定长样本流"，其余全部复用。 HSS 与 RTT（两种完全不同的传输语义）在 UnpackSamples 处合流， 之后触发、统计、绘图、导出、甚至"导入离线文件"都共用同一条数据通路 （导入 = 清环 + 强制有时间戳 + 灌进同一个解包器）。 OpenScope 的网络模块应照搬这条分界线：本地后端 / 远端后端 / 文件回放，三者同构。

③ RTT-Plus 让主机决定采什么、目标端零 ELF 依赖。 下行通道 JScope_Config 送变量表，上行 JScope_Data[_t] 回数据； VarFormat 模式甚至把布局编码进通道名（JScope_t4i4f4）。 对 OpenScope 的"远端无 ELF 也要显示波形"，这是成本最低的方案 —— 但必须先做 §17#4 的字节抓取实验，因为 J-Scope 9.66 实际发的格式与 SEGGER 文档不一致。

18.2 抄 / 不抄对照表

项裁决理由（含证据）
运行时按名解析后端 DLL（GetProcAddress + 懒加载 thunk）抄同一 exe 适配任意 J-Link 版本；OpenScope 已有此模式，继续用于 J-Link/ST-Link 双后端
「后端产出定长样本流」的抽象分界抄§18.1②；网络远端与文件回放可直接复用
单工作线程 + 环形命令队列 + id 分派 + 作业自销毁抄无锁消费者、代码量极小（§15.1）；但要补两件 J-Scope 没做好的事：满队列策略（J-Scope 原地睡 1 ms 轮询）与真取消（J-Scope 的"取消/超时"只是生产者不再等待，作业照样执行）
"锁内改状态 → emit 队列信号"回投 UI + worker 阻塞等 UI 的模态同步抄实测无 PostMessage/SetTimer/invokeMethod，全靠 Qt 队列连接；比 OpenScope 现有的 WM_* 自定义消息更省事，且天然跨平台
带签名守卫 + 尾部哨兵的调试堆（0xDEADBEEF、32×0xCE、块标签）抄（默认开）能直接报出"哪个标签的块被溢出多少字节"。注意 J-Scope 自己把开关 DAT_14285eb9c 写成只读 → 发布版守卫全关，等于白写；OpenScope 应默认开启但可关
分段日志：FUN_14003f830(段名) 进入 → 段内 ERROR/WARNING/INFO → 段末若有错弹一次汇总抄天然适配自动化 E2E（段名 + 级别 + 耗时可直接进测试断言），也是 OpenScope 多实例联调最缺的东西
QPC → µs 的单点换算（含频率缓存与首调用基准）抄§15.6；但别用 timeGetTime 做 ms 级调度（15.6 ms 分辨率，J-Scope 的 10 ms 周期实际 ≥15.6 ms）
RTT 跨读取 ≤64 B 残留拼接抄流式协议必备；比"丢弃半样本"健壮得多（§7.5）
JRAW 无头裸流格式的读写抄格式，加头互操作价值极高（J-Scope 能直接导入），但裸流离开工程不可解释；建议 OpenScope 默认写"魔数+版本+变量描述"头，另给 --jscope-compat 出裸流
每变量固定 64 MB 环 + 8 B 槽位不抄8 变量即 512 MB；应按类型宽度紧凑存储或分段落盘（§6.4）
固定 8,388,608 样本深度不抄OpenScope 有长时记录与历史回传需求，深度应可配/可落盘
时间戳用 uint32 µs（71.6 分钟回绕）不抄J-Scope 对回绕完全不做处理；OpenScope 应存 64 位或做回绕续接
CSV 的 %i 打印（无符号按有符号）与"物理下标"导出不抄uint32 > 2³¹ 显示为负；绕回后导出语义混乱；且 writeIdx==0 会跑 2³² 次（§10.3）
全局单例状态 + 一把大锁串起整个应用不抄J-Scope 是单实例桌面程序，这套在 OpenScope 的三实例网络测试里会直接撞车
栈上描述符投进跨线程队列；用全局对象指针当函数指针调用不抄§15 未知点里的两处隐患，纯属历史包袱
JLINKARM_DEVICE_SelectDialog 弹窗选型不抄与 OpenScope "不弹窗选芯片"的既定要求冲突
未声明 DPI 感知的清单不抄高 DPI 下靠系统位图拉伸，界面发虚（§1）

18.3 三个可以直接落地的接口草案

① OpenScope 的 J-Link HSS 后端（契约已完全确定）

/* 描述符数组：末尾补一个 {0,0} 终止项，sampleSize = 4 + Σsize */
typedef struct { uint32_t addr, size, r0, r1; } os_hss_var_t;   // 16 B/条

uint32_t off = 4;
for (i = 0; i < n; i++) { d[i] = (os_hss_var_t){ v[i].addr, v[i].size, 0, 0 }; v[i].off = off; off += v[i].size; }
d[n] = (os_hss_var_t){0};
rc = JLINK_HSS_Start(d, n, period_us, 1);        // rc: -2 探针内存不足 / -3 变量过多 / -4 目标不支持
if (rc >= 0 && JLINK_IsHalted()) JLINK_Go();

/* 10 ms 泵（OpenScope 侧用高精度等待，别用 timeGetTime） */
size_t bufSz = (2<<20) - ((2<<20) % sampleSize);
int nBytes = JLINK_HSS_Read(buf, bufSz);               // 返回字节数
if (nBytes > 0) os_unpack_samples(nBytes / sampleSize, buf);  // 与 RTT 共用

② 与 J-Scope 互通的数据文件（裸流 + 自描述头双模式）

/* 兼容模式（J-Scope 可直接 Import Raw）：无头裸流 */
for (i = 0; i < nSamples; i++) {
    uint32_t ts = ts_us[i];
    fwrite(&ts, 4, 1, fp);                     // 小端 u32 µs
    for (each var v) fwrite(var_ring(v) + i*8, v->size, 1, fp);  // 变量顺序 = 变量树顺序
}
/* OpenScope 原生模式：+ 魔数/版本/变量描述/单位，可长期归档 */
