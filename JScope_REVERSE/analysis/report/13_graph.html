10. 对 OpenScope 的启示（建议）

  1. 保留"100 px = 1 大格"这一硬约束。J-Scope 把网格间距、Y 分辨率、"N/div" 文本、YOffset 步长（0.5 格）、游标移动步长（0.1 格）全部绑在同一个 100 px 常数上，代码里找不到第二套坐标系。OpenScope 若沿用"每格 = 一个可读数量级"的设计，UI 文案与交互步长就能自然统一（也便于直接显示 us/Div、ms/Div、s/Div）。
  2. x/y 变换写成"双公式互为逆运算并各自二分查找"：J-Scope 同时有 像素→时间(FUN_140049830) 与 时间→像素(FUN_14004a0f0)，且用整数除法（(W+1)/100）导致末端 1 格轻微非线性。OpenScope 应统一用 double并只保留一套变换函数，避免"网格线与数据点对不齐"的像素级偏移。
  3. 不要照抄"逐样本 drawLines"的绘制策略。J-Scope 每帧对可见区间每个样本调一次 QPainter::drawLines（无 min/max 包络、无 LOD）。OpenScope 的 64 MB 环在高采样率+小 z 缩放时必然爆帧。建议：按像素列做 min/max 包络 + QPainterPath/批量 drawPolyline，或直接走 OpenGL/QPainter 的 drawLines(QLine*, count) 批量重载。
  4. 自动定标公式可借鉴，但应改成"只对变化量做，且允许降档"：J-Scope 的 YResolution = 2·max(|min|,|max|) / 格数 且只升不降（FUN_14004b830 只在 cur < need 时上调），一旦遇到一次尖峰，Y 分辨率就永远回不去；且它假设数据关于 0 对称。OpenScope 建议用 (max−min)/(格数−1) 并做滞回（降档需连续 N 帧满足），避免曲线被压平。
  5. 状态栏三项的语义要分开：FPS: 是单帧绘制耗时的倒数且被目标 FPS 节流（FUN_14004bc30）；Samples/s: 是最近一次读取周期的瞬时速率（并且 J-Scope 那版还偏大 10 倍）；Buffer: 报的是已分配缓冲内存而非"已用数据量"。OpenScope 至少应把"目标样本率 / 实际样本率 / 缓冲占用 / 丢帧数"分开显示，并显示掉帧计数（J-Scope 没有丢帧可视化，只有 % 占用）。
  6. 交互集：Zoom 用"档位表"（1-2-5 ×10^k）而不是连续缩放，好处是缩放永远落在可读刻度上；但 J-Scope 的"鼠标锚点固定"公式 (±0.5·(t_m−XStart)) 只对 ×2 精确，非 2 倍档位会漂移。OpenScope 应直接实现 XStart_new = t_m − (x_m − xoff)·Zoom_new/100 的精确锚定，并补上滚轮缩放（J-Scope 缺失）。
