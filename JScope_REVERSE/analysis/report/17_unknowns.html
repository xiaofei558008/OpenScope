本轮针对上一轮列出的未解项做了三件事：① 全镜像 RIP 相对引用扫描（重新同步式线性反汇编 108,121 条指令，覆盖 Ghidra 未识别为函数的代码）；② 对 JLink_x64.dll 做定向反汇编 （HSS 四个导出 + 能力查询 + 日志字符串）；③ 用 Ghidra 补建 8 个从未被创建的函数 （作业表里只有数据引用的处理器）。结果：10 项未解中 8 项已闭环，其余 2 项只剩"硬件/固件侧确认"。

17.1 已闭环（上一轮的未解项）

#问题结论与证据等级
1 JLINK_HSS_GetCaps 的 8 字节结构 caps 实际是 32 字节，字段如下（由 DLL 内部 JLINK_HSS_Start 的使用点反推）：
· +0x00 dword = 最大变量（数据块）数：cmp n, caps+0; ja → 返回 -3（"Too many variables"）；能力缺失时取回退值 5
· +0x04 dword = 最大采样率 Hz：DLL 自己就用 1e6 / caps+4 求最小周期 µs —— 与 J-Scope 的 TimeResUs 公式完全一致，回退值 50(Hz)→20 000 µs
· +0x08 dword = 能力位：bit1 决定 flags 的 bit0 是否保留（见下）
· 其余 20 字节在 Start 路径中未被读取		 观测
2 JLINK_HSS_Start 的 Flags=1 语义 DLL 侧确实解码了 flags： ecx = caps+8; and ecx,2; 然后 eax = flags & ~1; bt ecx,1; cmovae flags, eax —— 即 只有探针 caps+8 的 bit1 置位时，flags 的 bit0 才被保留，否则 DLL 静默把它清掉； 同时把"能力是否存在"记进 0x1816d4ac0。 flags 随后原样传给设备层（[vtable+0x528]），并出现在日志串里。 bit0 的物理含义在探针固件里，主机侧无法再挖 观测+固件侧
3 三个负返回码 -2/-3/-4 的来源 全部在 DLL 的 HSS_Start 里产生，与 J-Scope 的字符串一一对应： HasHss==0 → -4；n > caps+0 → -3；块数组 malloc(n*16)==NULL → -2。 J-Scope 只是把 rc 映射成文案 观测
4 DLL 版本门槛 0xC79B 版本解码函数 FUN_1400271f0 明确为十进制打包： major=v/10000, minor=(v/100)%100, rev=v%100（rev>26 → 后缀 zNN）。 故 0xC79B = 51099 → V5.10.99 —— 要求 J-Link DLL ≥ V5.10.99 才使用 HSS_GetCaps，否则退回固定 10 µs 周期 推导（编码已观测）
5 RTT 读缓冲大小 DAT_14085d1b0 的写入者 全镜像只有 2 处引用，且都是读（0x14003efc2 的 cmp 与 0x14003efc8 的 cmova，都在 FUN_14003ef60 内）→ 该变量永远是 0， 于是 readBufSize = max(0x2000, 0) = 0x2000： RTT 读取缓冲恒为 8 KB，"按通道缓冲自适应"的设计在本版本没有生效 观测
6 调试堆守卫开关 DAT_14285eb9c 的写入者 全镜像只有 4 处引用，全部是 cmp […], 0 读 （0x140043d43 / 0x140043d6c / 0x140043f1b / 0x140043fe7，都在分配器自身内） → 开关恒为 0：发布版本中签名/哨兵校验全部关闭， 带守卫的堆在本版本退化为"块头 + 标签"的普通 malloc 包装 观测
7 ≈30 MB 未引用静态区 确认全镜像零引用：RIP 相对扫描（108,121 条指令）在 0x1400a5d1f0–0x14285d1f0 区间没有命中任何一条指令， 与 Ghidra 的 4,837 项全局扫描一致。结论：纯虚拟预留（BSS 式），从提交到运行都不被访问， 对功能无影响；成因（遗留大数组 / 对齐填充）不可知 观测
8 作业处理器表中 7 项"未取到函数体" 16 项全部补齐（见 §2.1 表）：其中 6 个是 Ghidra 从未创建的函数， 本轮用 DecompAt.java 补建并反编译；0x14003d9a0 确认为 FUN_140046e80(job->data + 0x20) 的 Import Raw 垫片 观测

17.2 本轮新解出的行为（原报告未覆盖）

发现内容
暂停 = 一个字节 FUN_14003d7c0（作业 id 6 "Pause reading"）的全部实现是 mov byte [0x140096DD0], 1。该全局正是 UnpackSamples 里 "跳过逐变量存储"的开关（FUN_14003ef00 → cVar3 分支）： 暂停时数据照读照解包，但每个样本都不落环 —— 与 UI 文案 "all incoming data samples are discarded" 精确对应。开始采集（FUN_14003d5c0）把它清 0， 停止（FUN_14003d7d0）置 1
日志回调是空桩 FUN_1400423e0 组装 "ERROR: %s" 后调用 0x14000a760(MainWindow*, msg) —— 而 0x14000a760 是一条 ret 0 指令 + CC 填充（3 字节空函数）。 真正的日志累积发生在同一个函数里：无条件追加到 4 KB 全局缓冲 DAT_14285db80 并给错误计数 +1， 段结束时由 FUN_14003e9a0 判定（有错 → 错误框；无错但有内容 → 信息框）。 J-Scope 既不写日志文件，也没有活的 UI 日志接收者
作业完成回调 默认完成回调 FUN_140040e10：若 job->data 非空则释放 data，否则释放 job 本身 （作业自销毁）。"打开工程"用专属回调 FUN_140042eb0：把 job->rc 分档写进 DAT_14286d37c（0=成功 / 2=取消）后再走默认释放
启动动作写注册表 作业 id 14（Set AppStart action，FUN_14003dc70 → FUN_140042750）把 job 负载里的 DWORD 写进注册表值 DontShowAgainStartJScope（REG_DWORD） —— 即"下次启动显示欢迎框 / 直接新建工程"的选择，与 §16 的向导分支闭合
保存工程的返回值链 FUN_14004eb40：仅当工程被标记为已修改才写盘 → FUN_1400471d0 写 XML → 成功则记日志 "Project saved successfully"、记住路径、清"已修改"标志； 失败则 "Failed to save project file"。 "另存为"（FUN_14004ebc0）先弹 "Save project as" / "J-Scope project files (*.jscope)" 对话框
关闭流程的三个标志 MainWindow+0x342 ≠ 0 → 直接关闭（退出中，跳过所有对话框）； +0x341 ≠ 0 → 弹"新建工程/配置"向导（FUN_140057220）， 其 QDialog::exec 结果存 +0x33C； +0x340 ≠ 0 → 弹配置对话框（FUN_14002a410）；两者皆 0 → 不弹
JLINK_HSS_Read 返回字节数 DLL 侧确认：mov eax,[reply]; test eax,eax; jle skip; mov r8d,eax; memcpy(dst=调用者缓冲, src=内部回复, eax) —— 返回值就是拷进调用者缓冲的字节数，J-Scope 的 nBytes/sampleSize 用法正确

17.3 仍然开放（只剩需要硬件的两项）

#问题现状一次实测即可定案
A 采样率显示 10 倍因子 本轮把单位链再核了一遍，反而更确定了： ① FUN_140043050 除以 freq/1e6 ⇒ 返回 µs； ② 独立的第二处调用点 FUN_140039140 把超时（ms）×1000 后再与 FUN_140043970() 比较 —— 单位确实是 µs； ③ 分母 DAT_14085d1ec 在 UnpackSamples 里就是"样本数"； ④ 显示路径 FUN_14003eb00 → FUN_140050030 只做 /1000 的 k 换算，无补偿。 故 rate = n×10⁷/µs 恒为真实值的 10 倍 推导（三处独立证据一致） 固定 HSS 周期（如 100 µs）采 10 s，比较状态栏读数与"样本数/时间"。 若确为 10 倍，则 J-Scope 状态栏的 Samples/s 一直是错的（或它有意显示 0.1 s 尺度）
B RTT-Plus 配置串与 UM08028 文档不一致 二进制实测 16 B/条 + 12 B 零终止（§7）；文档写 8 B/条 + 8 B 零终止。 本轮无法再进一步 —— 目标端固件不在本机 写一个只开下行通道的固件，把收到的字节原样打印（已有 20 行示例可改）
C flags bit0 / caps bit1 的物理含义 主机侧已挖到底：DLL 只做"能力门控"（caps+8.bit1 决定 flags.bit0 是否保留）， 真正的语义由探针固件解释 用同一块探针分别传 flags=0/1 抓 HSS 数据：若时间戳行为不同即可定性
