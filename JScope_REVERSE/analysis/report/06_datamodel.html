06双环数据模型

这是 J-Scope 高性能绘图的核心设计：一个全局时间戳环（静态 32 MB）+ 每变量一个数据环（堆上 64 MB）， 两者深度相同（8,388,608 样本），索引一一对应。绘图、游标取值、导出全部靠"时间戳环索引 ↔ 变量环索引"的直接对应关系， 没有任何时间查找。

时间戳环 tsRinguint32[0x800000] · 32 MB · .data 静态

索引 writeIdx (DAT_14285da80) · 上一索引 lastIdx (DAT_14285da7c) · 高水位 wrapped (DAT_14285da78) · 当前值 curTs (DAT_14285da84)

变量数据环 dataBuf每变量 64 MB · 固定 8 B/样本槽位

memcpy(dataBuf + writeIdx*8, sample + v->offset, v->size) —— 1/2/4/8 字节的值都占 8 字节槽位

6.1 环索引语义（FUN_14003fa70）

for (each sample) {
    StoreTimestamp(sample);                 // tsRing[writeIdx] = sample->ts（详见 6.2）
    curTs = tsRing[writeIdx];
    for (each 变量 v) {
        StoreVarSample(v, sample);          // memcpy 到 v 的环（★ 先存后判触发）
        rc = IsFirstSample() ? SKIP : TriggerEval(&trig, v, prevPtr, curPtr);
        if (rc == 0) {  /* 未触发 */  v->lastPtr = 仅当 v 是触发符号时更新;  v->hasData = 0; }
        else {
            if (rc == 1) { writeIdx = 0; wrapped = 0; }   // ★ 触发命中：环从头开始记录
            if (rc == 2 || rc == 3) { /* 无触发配置 / 已触发过 */ }
            v->lastPtr = v->dataBuf + writeIdx*8;
            UpdateStats(v);                 // min / max / 滑动平均
            v->hasData = 1;
        }
    }
    if (writeIdx < wrapped) wrapped++;      // 高水位随写指针推进
    writeIdx++;
    if (writeIdx > 0x7FFFFF) { writeIdx = 0; wrapped = 1; }  // 环绕
    lastIdx = writeIdx - 1;
}
全局语义（由 FUN_14003ead0 / FUN_140041540 / FUN_14003ff40 三处用法反推）
writeIdx下一个待写槽位；取值 0…0x7FFFFF
lastIdxwriteIdx - 1（上一次写入的槽位），用于时间戳合成与"上一采样值"
wrapped高水位 + 是否已满：环绕前置 0（缓冲按 lastIdx/0x800000 计填充率）；环绕后它始终等于 writeIdx+1， 于是 lastIdx < wrapped 恒真 → 填充率显示 100%（缓冲确实已满）
curTs当前样本时间戳（供 UI 读取"最新时刻"）

6.2 时间戳语义（FUN_14003ff40）

if (mode == HSS)            tsRing[writeIdx] = sample[0];        // 探针给的 µs，原样存
else if (rttWithTimestamp)  tsRing[writeIdx] = sample[0];        // 目标给的 µs，原样存
else {                       // RTT 无时间戳 → 合成 100 µs 均匀栅格
    if (writeIdx != 0)        tsRing[writeIdx] = tsRing[lastIdx] + 100;
    else if (wrapped < lastIdx) tsRing[0] = tsRing[lastIdx] + 100;  // 刚环绕，继续栅格
    else                     tsRing[0] = 0;                    // 真·首样本 t=0
}

与二进制中的告警串逐字吻合： 

"RTT channel is set up to provide no timestamp!"
"Without timestamp J-Scope will assume that data points are uniformly distributed with a gap of 100 [us] each."

时间基是纯 uint32 µs：计数在 2³² µs ≈ 71.6 分钟后回绕。 J-Scope 不做任何展开/续接处理 —— 长时间记录会出现时间戳回绕（波形横轴跳变）。这是重实现时必须修的坑。

6.3 统计量与采样率

量计算（FUN_140042ac0 / FUN_140041710 / FUN_14003ead0）备注
yMax / yMin逐样本与 -DBL_MAX / +DBL_MAX 初值比较，按变量 TypeID 分派到具体类型转换（float/double/有符号/无符号 8·16·32 位）浮点分支带 NaN 保护（x != x 则不更新）
yAvg（Moving average）avg = ((writeIdx-1)*avg + x) / writeIdx —— 用环索引当样本计数⚠ 环绕后或触发重置后 writeIdx 归零，平均值会"重新开始"——J-Scope 的既有行为
缓冲填充率FUN_14003ead0：wrapped > lastIdx ? 100.0 : lastIdx*100/0x800000状态栏 Buffer: … (0x800000 samples), N%
采样率FUN_140041710：rate = numSamples * 107 / elapsed，elapsed = FUN_140043970()（QPC 差值 ÷ (freq/1e6) = µs）每 10 ms 窗口刷新一次；≥1000 显示 kSamples/s，否则 Samples/s

一处需要实测的量纲疑点：按上面的单位，numSamples × 10⁷ / µs 比真实样本率 numSamples × 10⁶ / µs 大 10 倍。两种可能：① FUN_140043970 实际返回的是 100 ns 单位（则该式为真值）； ② 这确实是 J-Scope 的一个显示 bug。静态分析无法判定 —— 挂上 J-Link、用已知周期的 HSS 跑一次、对照真实采样率即可确认。 未知

固定 8 B 槽位的唯一好处是索引 O(1) 且与类型无关（dataBuf + idx*8 一条指令算出任何类型的位置）， 代价是 4 字节变量浪费 50%、1 字节变量浪费 87.5%。J-Scope 选择"用内存换代码简单"， 因为它是 64 位桌面程序、且深度固定 8 M 样本。 OpenScope 若要支持长时间记录 / 网络回传，应按类型宽度紧凑存储（或分段落盘） —— 这是本次逆向里最明确的一条"别抄"。
