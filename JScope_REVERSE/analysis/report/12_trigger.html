1. 概述

1.1 一句话结论 观测

J-Scope 的触发是「命中即从触发点重开记录」模型：

  1. 每收到一个样本，所有变量的原始数据都无条件写入 8 字节/样本的环形缓冲（FUN_14003feb0）；
  2. 随后对每个变量调用一次触发判定 FUN_1400415a0（返回 0/1/2/3）；
  3. 若返回 1（首次命中）：把全局环形写指针 writeIdx 和 wrapped 清零，该变量的 hasData(+0x388)=1，触发锁存位置 1；
  4. 若返回 0（未命中）：该变量 hasData=0 —— 曲线不绘制（数据仍在环里，只是"不可见"）；
  5. 若返回 2（触发未使能）/ 3（已命中过）：等同"放行"，hasData=1，且不重开记录。

绘图端只画 hasData(+0x388) != 0 的变量（chunk_006.c:2450：ShowInGraph(+0x35E) && hasData(+0x388) && !disabled(+0x380)）。因此触发使能前图上是空的，命中瞬间 x 轴从 0 重新开始。

Ghidra 已识别的类：TriggerWidget（RTTI .?AVTriggerWidget@@ @ 0x140097B68，类名字符串 @ 0x140073A20）。

2. 数据结构 观测

2.1 触发结构体（0x18 = 24 字节）

由 FUN_1400561b0（分配 0x18 并逐字节初始化）与 FUN_14004ea20/ed00（整块搬运 24 B）共同确定：

struct Trigger {          // sizeof = 0x18
  VarRecord *symbol;      // +0x00  触发符号（指向变量记录）；0 = 未选择
  double     level;       // +0x08  阈值（double）
  uint8_t    on;          // +0x10  触发使能   ← XML "On"
  uint8_t    auto_;       // +0x11  引擎从不读取（见 §7.3）  ← XML "Auto"
  uint8_t    rise;        // +0x12  上升沿     ← XML "Rise"
  uint8_t    fall;        // +0x13  下降沿     ← XML "Fall"

证据（均为 观测）：

  • 构造：FUN_1400561b0 中 FUN_140043d10(0x18) 后写 +0x11,+0x14,+0x13,+0x10,+0x12（chunk_007.c:2093-2101）。
  • 字段语义：比较器读 [rcx+0x12]/[rcx+0x13]（沿选择）、[rcx+8]（阈值），写 [rcx+0x14]=1（0x140041090: c6411401 mov byte ptr [rcx+0x14], 1）。
  • FUN_1400415a0 读 [rcx+0x10]（使能）与 [rcx+0x14]（锁存）。
  • 阈值确为 double：movsd xmm1, qword ptr [rcx + 8]（0x14004104E）。

返回值 含义 调用方动作（§5）

要点 观测：

  • on 检查在符号匹配之前，triggered 检查也在之前。所以命中后（triggered=1）所有变量（含非触发符号）都返回 3 → 全图恢复绘制；
  • 触发符号以外的变量在等待触发期间恒返回 0，因此"触发前不显示"对全体变量统一生效；
  • 类型不支持（bool 5、int64 13、uint64 9、TypeID 3/4）→ 恒 0 → 选中这类符号做触发会永远不触发（UI 不做任何提示）[观测/推断]。

修正既有报告 §6.3：那里写的是"触发判定 → 0/1/2/3 → 命中则调 FUN_140042ac0"，但 FUN_140042ac0 实际是 min/max/avg 统计累加器（不是触发处理），且它接收两个参数 (v, &ring[writeIdx])（Ghidra 的 C 输出漏了第二个实参，反汇编 0x14003FB7D/0x14003FB8B 可见 lea rdx,[rax+rcx*8]; call）。

4.1 统一判定式

命中 = (rise && prev <  level && cur >= level)      // 上升沿：自下方穿越阈值
    || (fall && prev >  level && cur <= level)      // 下降沿：自上方穿越阈值

（level 为 double；整数先精确转 double 再比；两侧都取闭区间，即"等于阈值"算命中。）

4.3 NaN 处理 [观测/推导]

无任何显式 NaN 分支；全部依赖 comisd 的无序语义：

asm

comisd xmm1, xmm0        ; 若任一操作数为 NaN → ZF=PF=CF=1
jbe    <skip>            ; CF|ZF → 取跳转 → 本方向不成立
...
comisd xmm0, xmm1
jae    <hit>   (rise)    ; CF=0 才命中 → NaN 时 CF=1 → 不命中
jb     <no-hit>(fall)    ; CF=1 才命中 → NaN 时 CF=1 → 命中路径被跳过

推导 结论：prev 或 cur 为 NaN（含 ±inf 与 NaN 混用）时两个沿都不会命中，也就是说 NaN 既不会误触发也不会"卡住"某个沿。若 OpenScope 用 C 写 prev < L && cur >= L，IEEE 语义与之一致，无需额外 NaN 分支（前提：编译不加 -ffast-math）。

5.3 命中瞬间的两处索引不一致 推导（潜在缺陷，OpenScope 应避免）

  1. writeIdx 的归零发生在同一变量的 for 循环内部：链表顺序在触发符号之前的变量，其本样本已写在旧下标；在它之后的变量，因 FUN_14003feb0 读的是 LIVE 的 writeIdx（已为 0），会写进 index 0。→ 同一样本内不同变量落在不同下标。
  2. 归零后立刻 curPtr = ring + 0 并 FUN_140042ac0(v, ring+0)，但触发符号自己的本样本被写到了旧下标 → Value: 显示与 min/max/avg 会吃到 index 0 上的陈旧值（首次触发时通常为 0）。 时间轴同理：tsRing[0] 是旧值，直到下一帧才正确。

这两点不影响"能用"，但会让触发首帧的触发符号读数/统计偏一帧。推断（反汇编确定，是否被用户观察到未验证）

9. 对 OpenScope 的启示（具体、可执行）

  1. 触发状态直接放进"当前工程设置"结构体里，就能白拿持久化与加载即生效。 J-Scope 把 Trigger 放在工程块 +0x5D0（= LIVE 状态本体），于是"存盘 = 写 XML"、"读盘 = memcpy"，全程没有一句"apply trigger"的代码。OpenScope 若已有一个 Settings/Project 单例，建议把 trigger 作为其成员（而不是另立全局），并让 XML 读写与内存布局一一对应。
  1. 采集线程用"快照 → 改 → 守卫写回"代替锁。 save(FUN_14004ea20) / apply(FUN_14004ed00：仅当有差异且工程已打开) 这一对是并发下最省事的做法：采集线程每批数据开头取一次快照（J-Scope 是 10 ms 一取），UI 线程随时改自己的副本再写回。代价是一个读批次（约 10 ms）的陈旧窗口 —— 对触发这种低频配置完全够用。注意 J-Scope 的 apply 内部还有 inc [0x142865068]（置"工程已修改"），OpenScope 可同样用它来驱动"未保存修改"提示。
  1. "命中即重开记录"可以用极低成本实现，但要在样本循环外归零索引。 骨架：if (r==1) { writeIdx=0; wrapped=0; } + 每变量一个 hasData 标志位控制绘制。J-Scope 把归零放在变量循环内部，导致同一样本内不同变量下标不一致、触发符号首帧取到陈旧值（§5.3）。OpenScope 应在处理完整个样本（所有变量）之后再归零，并把该样本显式写到 index 0，可顺手修掉这两个瑕疵。
  1. 比较器用"类型 → 函数表"分派，并明确列出不支持触发的类型。 TypeID→比较器跳转表（§4.2）比每样本 switch 更好维护。同时注意：J-Scope 对 bool、int64、uint64（以及它的 float16/float128）没有比较器，用户选中会"永远不触发"且无提示 —— OpenScope 要么补齐（int64/uint64 用整数比较，注意 (double) 转换在 >2^53 时丢精度），要么在符号下拉框里禁用这些类型。
  1. 整数阈值比较务必先升为 double 再比（与 J-Scope 对齐），浮点 NaN 不需要特判。 全部 8 个比较器都是"载入 → 转 double → comisd"，NaN 因无序标志自然两个沿都不命中（§4.3）。OpenScope 若写成 prev < L && cur >= L / prev > L && cur <= L 且不开 -ffast-math，行为与 J-Scope 完全一致 —— 便于将来做波形/触发结果互校。
  1. UI 抄这个最小集合即可，并把"启用"合并进"沿选择"。 实测 J-Scope 的触发栏只有：Trigger control: 标签 + 3 个互斥 checkable 动作（Rising/Falling/Both；全不选 = 关）+ 1 个符号下拉（复用已选变量列表）+ 1 个带 QDoubleValidator 的阈值框 + 1 个只读值框（显示 %f 实时值或 "Triggered"，只在采集中才有内容），且整套控件只在"已打开工程 且 未采集"时可编辑（采集中变灰，§6.6）。另外，如果 OpenScope 不需要 "Auto"，就在数据结构里删掉该字段，别像 J-Scope 一样留下一个"能存能读但没人用"的死字段（§7.3）。
