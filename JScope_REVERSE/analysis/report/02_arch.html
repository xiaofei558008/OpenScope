2.1 作业（Job）模型 —— 标签即作业名

逆向中一个容易误读的点：那些 APP: <ReadPeriodic> 之类的字符串不是作业名，而是堆分配标签 —— 它们由带守卫的自研分配器 FUN_140043d20(size, label) 记录，用于内存审计。作业对象本身的布局极简：

作业对象（0x28 字节，FUN_14003d5c0 现场构造）

struct Job {            // 0x28 B，由 FUN_140043d20(0x28, "APP: <...>") 分配
    Job    *next;       // +0x00  全局作业链 DAT_14085d150
    void   *data;       // +0x08  作业负载（含各自的 out 指针与结果码）
    int   (*fn)(...);   // +0x10  执行体
    int     period;     // +0x18  周期（ms）；ReadPeriodic 固定写 10
    int     rc;         // +0x1c  结果码（负数=失败，UI 据此弹框）
};

2.2 全局模型：双缓冲 + 临界区

配置与工程设置各有一份锁保护的全局主副本，任何线程要读就先"取快照"到自己栈上/堆上，改完再"提交"。 这是 J-Scope 避免数据竞争的唯一手段 —— 简单、粗暴、有效：

2.4 一次采样的数据流

J-Link 探针 ──HSS 后台采样──▶ 探针内部缓冲
                                  │  JLINK_HSS_Read(buf, ~2 MB)     // 工作线程，每 10 ms
                                  ▼
                        UnpackSamples(FUN_14003fa70)              // HSS 与 RTT 共用
                          ├─ 时间戳 → tsRing[writeIdx]            // 32 MB 静态环
                          ├─ 每变量 → v->dataBuf[writeIdx*8]      // 每变量 64 MB 堆环，8 B 槽位
                          ├─ 触发判定 FUN_1400415a0（逐变量）      // 命中则重置环索引，从头记录
                          └─ 统计 FUN_140042ac0（min/max/avg）     // 刷新表格三列
                                  ▼
                     主线程 QTimer 到期 ──▶ 重绘波形 + 刷新状态栏/表格
                                             // 环形缓冲 → 每像素列取点，与采样率解耦

架构上最值得抄的一点："采集后端只负责产出带时间戳的定长样本流"。 HSS 与 RTT 两条完全不同的传输路径（一个主机轮询、一个目标推送）在 UnpackSamples 处合流，之后的数据模型、触发、统计、绘图、导出全部复用。 OpenScope 的网络采集（本地采集→压缩→远端显示）应当照搬这个分界线。
