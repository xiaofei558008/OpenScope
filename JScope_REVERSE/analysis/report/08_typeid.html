08类型系统（TypeID）

TypeID 存于符号记录 +0x314，是"这个变量怎么解释字节"的唯一开关： 采样统计、触发比较、CSV 导出、树中是否可勾选，全部按它分派。 全程序只有三处产出 TypeID（ELF/DWARF 分类器、RTT VarFormat 解析器、位域分支），完整证据见 §14.3。

TypeID类型树中可选判定依据（FUN_140040050，除非另注）
0不支持 / 未知✘其余全部情况（含 +0x3D8 已置位、类型名不匹配、宽度非法）
1float32✔size==4 && type=="float"；MaxValue = FLT_MAX
2float64✔size==8 && type=="double"；MaxValue = DBL_MAX
3—（保留/未使用）—✘无任何代码产出该值；树中一旦出现即禁用
4—（保留/未使用）—✘同上
5bool✔size==1 && (type=="bool" || type=="_Bool")；MaxValue = 1.0
6uint8✔无符号 + size 1；MaxValue = 255
7uint16✔无符号 + size 2；MaxValue = 65535
8uint32✔无符号 + size 4；MaxValue = 4294967295
9uint64✘无符号 + size 8；可分类但树中被禁用（"Symbol type is not supported"）
10int8✔有符号 + size 1；MaxValue = 127
11int16✔有符号 + size 2；MaxValue = 32767
12int32✔有符号 + size 4；MaxValue = 2147483647
13int64✘有符号 + size 8；同样被禁用
14 (0xE)位域✔DWARF DW_AT_bit_size 存在时（FUN_1400404c0）；位宽/位偏移存 +0x338 / +0x33C，取样时 (raw >> shift) & ((1<<width)-1)（FUN_14003eaa0）

本轮修正的两处旧结论：

① TypeID 14 = 位域（不是"另一个被禁类型"）——这是上一轮完全没发现的类型， 而且它可以在树中被选中并采样（对寄存器位域极有用）。

② TypeID 3/4 没有任何产出点：上一版报告推测的 "long double/float128" 与 "half" 在本版本代码里 找不到任何支撑——它们只是枚举里保留的槽位（历史遗留），手工改 .jscope 才会出现，且一律禁用。

可观测类型 = 1,2,5,6,7,8,10,11,12,14；不可观测 = 0,3,4,9,13 —— 也就是说 J-Scope 9.66 无法观测任何 64 位整型变量（uint64/int64 只能在 ELF 里被分类，但树上不给勾选框）。
