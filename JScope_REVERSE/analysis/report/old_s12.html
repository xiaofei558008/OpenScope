12对 OpenScope 的启示

12.1 三条最有价值的结论

  1. HSS 是 OpenScope 高速采样的现成答案。 JLINK_HSS_Start(变量表, 数量, 周期µs, 1) + 周期 JLINK_HSS_Read 到 2 MB 缓冲。 探针自主按周期采样并缓存、带 µs 时间戳、主机批量取走 —— 采样率与 USB 往返解耦。 这正对应 request.md 第 15 条「第二步：真 µs 采样（片上缓冲，XCP 式）」， 且不需要在 MCU 上跑采样代码（HSS 走 AHB-AP 后台访问，不占用 DWT/SWO）。
    注意：HSS 属 J-Link SDK 功能，无公开文档；§05 是可直接使用的调用契约。
  2. HSS 与 RTT 可以共用同一数据模型。 J-Scope 把两者的字节流都喂给同一个 UnpackSamples， 统一成「定长样本 + 首 4 字节 µs 时间戳」。 OpenScope 的网络模块（request.md 第 14 条）应当照搬这个抽象： 采集后端只负责产出「带时间戳的定长样本流」，压缩 / 传输 / 绘图全部复用。 这也直接解决「本地 ST-Link/J-Link 采集 → 网络传给远端」的接口设计。
  3. RTT VarFormat 让目标端零 ELF 依赖。 通道名 JScope_t4i4f4 自带完整布局。OpenScope 若要在网络对端（无 ELF）显示波形， 这是最省事的方案 —— 发送方把变量布局编码进通道名 / 握手包即可。

12.2 建议抄 / 不抄

项建议理由
运行时按名解析后端 DLL抄已在 OpenScope 网络模块验证过的模式；同时兼容 J-Link / ST-Link
双环数据模型（时间戳环 + 每变量环）抄，改进索引 O(1)、绘图简单；但 8 B/样本固定槽位太浪费
8,388,608 样本固定深度不抄应改为可配置深度或分段落盘（OpenScope 已有历史回传需求）
每变量 64 MB 预分配不抄8 变量即 512 MB；应按类型宽度紧凑存储（1/2/4/8 B）
时间戳统一为 µs、uint32抄与 J-Scope 对齐便于互操作；注意 2³² µs ≈ 71.6 分钟后回绕
无时间戳时合成 100 µs 栅格抄低成本兜底，避免绘图断链
RTT 跨读取 ≤64 B 残留拼接抄流式协议必备；比「丢弃半样本」健壮得多
10 ms 采样泵 + 2 MB 批读抄让探针 / 目标做缓冲，主机不与采样率耦合
带守卫的自研堆分配器可选调试期价值高（能抓越界 / 野指针），发布期有开销
JLINKARM_DEVICE_SelectDialog 选型弹窗不抄与 request.md 第 17 / 21 条「不要弹窗选芯片」直接冲突

12.3 已知坑

  • JLINK_HSS_Start 第 4 参数为 1（flags）观测，语义未知。
  • caps.field_at_4 的单位需实测确认（§04 末）。
  • TypeID 3/4 语义未确证（§08）。
  • -USB / -IP 选项必须与 -openprj 同用，否则报错 —— 因连接参数来自工程文件。
  • RTT 模式强制要求指定目标器件：In RTT mode specifying the target device is mandatory.
