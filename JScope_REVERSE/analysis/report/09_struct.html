09数据结构总览

J-Scope 的内部对象全部由自研分配器分配，没有 C++ 类实例化痕迹（除了 Qt 与几个对话框类）—— 核心对象是"裸结构体 + 手写初始化函数"。这解释了为什么反编译产物如此"可读"： 字段偏移在代码里直接可见。下面四张表是重实现时真正需要对齐的东西。

9.1 变量记录 / 符号树节点（0x3F0 字节）观测

分配点：FUN_140040ab0 — Alloc(0x3F0)，无标签；同一结构既当"变量"又当"树节点"

struct SymbolNode {           // 0x3F0 B，字段偏移全部来自反编译交叉验证
    uint32_t  nodeKind;      // +0x000  节点种类（变量/数组/结构体…）
    char      Name[0x104];    // +0x004  叶名（XML 属性 Name）
    char      NameWithParents[0x108]; // +0x108  全路径名
    char      Type[0x100];    // +0x110  类型名（"float"/"unsigned int"/…）
    char      File[0x104];    // +0x210  来源文件
    int       TypeID;         // +0x314  见 §8（0=不支持）
    uint32_t  Address;        // +0x318  绝对地址
    uint32_t  Size;           // +0x31C  字节数
    int       elemCount;      // +0x320  数组元素数
    void     *elemList;       // +0x328  元素节点链（每个 0x10 B 节点，释放时逐个 Free）
    char      isSignedFloat;  // +0x330  bool/float 时=0/1；整型时 0=无符号、1=有符号
    uint32_t  bitWidth;       // +0x338  位域：位宽
    uint32_t  bitShift;       // +0x33C  位域：位偏移
    int       DrawStyle;      // +0x348  0=线 1=点 2=点+线 3=竖线
    double    YOffset;        // +0x350  像素偏移
    int       YResolution;    // +0x358  每格量程
    bool      IsAutoConfig;   // +0x35D
    bool      ShowInGraph;    // +0x35E  默认 1（初值 0x00010000 写 +0x35C）
    bool      ShowCheckBox;   // +0x35F  树中是否给勾选框
    void     *treeItem;       // +0x360  对应的 QTreeWidgetItem*
    void     *selNode;        // +0x368  选中链节点（移除时置 0）
    void     *color;          // +0x378  QColor*（RGB 三元组）
    bool      hasData;        // +0x388  本周期是否有有效样本
    uint32_t  sampleOffset;   // +0x38C  ★ 在采样包内的字节偏移
    uint64_t  field390;       // +0x390  每周期复位（用途未定）
    double    yMaxSampled;    // +0x398  初值 -DBL_MAX
    double    yMinSampled;    // +0x3A0  初值 +DBL_MAX
    double    yAvgSampled;    // +0x3A8  滑动平均
    double    MaxValue;       // +0x3B0  类型量程上限（自动定标用）
    longlong  lastSamplePtr;  // +0x3C8  上一次写入样本在环内的地址（触发比较的"prev"）
    void     *dataBuf;        // +0x3D0  ★ 该变量的 64 MB 数据环
    SymbolNode *children;    // +0x3D8  子节点链 / 变量表尾指针（懒创建）
    SymbolNode *children2;   // +0x3E0  第二条子链（析构函数 FUN_140040bd0 同时遍历两者）
};

MaxValue（+0x3B0）是自动定标的基准：bool→1.0、float→0x47EFFFFFE0000000(FLT_MAX)、 double→0x7FEFFFFFFFFFFFFF、uint8/16/32/64→255/65535/4294967295/1.8446744e19、 int8/16/32/64→127/32767/2147483647/9.223372e18。这些常量在 FUN_140040050 里逐一可见 —— 也就是"J-Scope 认为这个类型的值最大能到多少"。

9.2 配置结构 Configuration（0x5BC）观测

偏移字段说明 / 证据
+0x000TargetDevice[0x80]器件名；空或查不到 → 弹 JLINKARM_DEVICE_SelectDialog
+0x080ElfFile[0x400]ELF 路径（"The elf file at\n%s\nwas deleted or moved…" 直接引用该偏移）
+0x38CScriptFile[0x80]→ JLINKARM_ExecCommand("ScriptFile = %s")
+0x490IpAddress[0x80]→ JLINKARM_SelectIP()
+0x510Nickname[0x80]→ JLINK_EMU_SelectByUSBNickname()（优先于序列号）
+0x594int SerialNo→ JLINKARM_EMU_SelectByUSBSN()；0 = 不指定
+0x59Cint TargetInterface0=JTAG · 1=SWD · 7=JTAG 变体 → JLINKARM_TIF_Select()
+0x5A0int InterfaceSpeedkHz → JLINKARM_SetSpeed()
+0x5A4char IsRTTSession0=HSS（异步）, 1=RTT（同步）
+0x5A5char IsRTTWithTimeStampRTT 上行通道带 t4（或存在 JScope_Data_t）时置 1
+0x5A6char IsRTTPlusRTT-Plus：下发给目标端变量表
+0x5A8int SamplingPeriodµs → JLINK_HSS_Start 第 3 参；默认 1000
+0x5ACint ConnectionType0=USB（昵称/序列号）· 2=TCP/IP · 4=会话（寄生模式）
+0x5B0int JTAG_DRPre仅 JTAG 使用；真正下发给 JLINKARM_ConfigJTAG() 的是 +0x5B4
+0x5B4int JTAG_IRPre
+0x5B8char SessionModeConnectionType==4 时置 1 → 停止采集时跳过 JLINK_HSS_Stop

读这一节前必须知道的一个陷阱：XML 读写用的是"项目结构"基址（比运行期 Configuration 高 8 字节）。 同一字段在两处的偏移天然相差 8，若不加区分会得到自相矛盾的字段表：

字段写入方读的偏移（运行期 C）读取方写的偏移（项目结构 P = C−8）换算
IsRTTSessionC+0x5A4P+0x5AC0x5AC−8 = 0x5A4 ✓
SamplingPeriodC+0x5A8P+0x5B00x5B0−8 = 0x5A8 ✓
InterfaceSpeedC+0x5A0P+0x5A80x5A8−8 = 0x5A0 ✓
JTAG_IRPreC+0x5B4（送 ConfigJTAG）P+0x5BC0x5BC−8 = 0x5B4 ✓

因此本报告修正三点：① JTAG_IRPre 在 +0x5B4（+0x5B0 是 DRPre）； ② +0x5B8 不是"JTAG 配置值"而是会话模式标志（Connection==4 时置位， 停采时据此跳过 JLINK_HSS_Stop）；③ 所谓"+0x5A8 既是接口速率又是采样周期"的字段重叠 并不存在——那是把 P 与 C 的偏移混看的产物。

另有独立于配置的触发结构（0x18 字节，全局 DAT_14285d9e0）与 作业对象（0x28 字节，见 §2.1）、 动态缓冲区（DYNBUFFER：基址 + 容量 + 当前长 + 越界回调，见 dumps/dynbuf.txt）。

9.4 内存分配器：带签名守卫的自研堆

所有非 Qt 对象都走 FUN_140043d20(size, label) / FUN_140043d10(size)， 释放走 FUN_140043e60(ptr)。它在 malloc 之上加了块头与校验： 

"Wrong alloc signature in memory block !"          // 释放/校验时签名不符 → 野指针或越界写坏了块头
"Buffer overflow in memory block. %d ..."          // 尾部哨兵被改写 → 缓冲溢出
"DYNBUFFER: dynamic buffer" "Cannot allocate %d bytes of memory for dynamic buffer"
"Insufficient memory!"

标签（"APP: <ReadPeriodic>"、"RTT read buffer allocation"…）随块存储， 用于出错时定位与内存审计。这是调试期价值高、发布期有开销的经典取舍（详见 §15）。
