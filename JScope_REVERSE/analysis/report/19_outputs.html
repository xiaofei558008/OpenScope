19.2 复现方法

# 1) 导入 + 全量分析（约 65 s；工具链见 RESTORE.md）
tools\run_ghidra.bat

# 2) 全量反编译 + 全局变量导出
tools\run_all.bat            # DumpAllDecomp(250) + DumpGlobals

# 3) 定点分析（对已导入工程重复跑脚本，不必重新分析）
tools\run_script.bat DumpOverview.java
tools\run_hss.bat            # 或 run_g.bat / run_globals.bat …

# 4) 生成报告页
python analysis\report\build.py     # 拼装 analysis/report/*.html → report.html

两个必须知道的工具链坑：① .bat 里必须显式 set JAVA_HOME=…\tools\jdk-21.0.12.1+1； ② 不要在 Git Bash 里用 cmd //c "…带引号或正则的参数…" —— 引号会被吞掉或转义错乱， 每次调用写一个专用 .bat。Ghidra 脚本里 Pattern.matcher(s).matches() 是整串匹配，子串匹配要用 .find()。

19.3 外部佐证

  • SEGGER KB — UM08028 J-Scope：官方用户手册页。本轮用它对照 RTT 通道命名、JScope_Config/JScope_Data 语义、快捷键表与命令行选项表（发现 RTT-Plus 配置串格式与实现不一致，见 §7.7）。
  • SEGGER KB — J-Link High-Speed Sampling：确认 HSS 属 J-Link SDK 能力（无 API 细节，故本报告 §5 的契约来自二进制本身）。
  • JLink_x64.dll V9.66 内部字符串："HSS started: %d DataBlocks, %d (period_us), 0x%.8X (Flags)"、"Block %d: %d bytes @ 0x%.8X" 等，用于交叉验证 HSS 参数顺序与失败路径。
  • Qt 4.8.7（SEGGER 自建，2024-12-17）：QtCore4.dll / QtGui4.dll 版本资源。
  • 方法论参考：REA（morluto/rea）—— 区分「观测 / 推导 / 推断 / 未知」并保留证据出处。
