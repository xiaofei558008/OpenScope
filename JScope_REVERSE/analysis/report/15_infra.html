1. 作业（Job）系统

1.1 结论速览

  • 不是 Qt 的 QThreadPool/QtConcurrent，也不是 QTimer 驱动；而是 自研"命名 Job + 单工作线程 + 环形命令队列 + 处理器表" 的框架，线程名 "WORKER"，用 CreateThread 创建。
  • 两类作业并存：
  • 一次性命令作业（ring queue，32 槽，id 0..15 用处理器表分派）—— Init/Exit/ReadStart/ReadStop/ParseELFFile/SaveProject…
  • 周期作业（有序链表，due/period 毫秒字段，回调返回非 0 即自我注销）—— 只有 APP: <ReadPeriodic>（10 ms）。
  • 作业名字符串只是内存分配标签（FUN_140043d20(size,"APP: <ReadStart>")），不是运行时查找键；运行时靠 id（job+0x18） 分派。观测

struct DYNBUFFER {            // 源码里自报家门："DYNBUFFER: dynamic buffer"

6.1 高精度：QPC → 微秒

观测 要点：

  • 全局唯一基准 DAT_14285edb0（首个 FUN_140043990 调用时捕获）→ 返回值天然是"进程运行 tick 数"，不存在跨基准比较问题，也把"QPC 频率全局"从"每次调用查频率"简化成一次性 DAT_14285eda0/eda8/edac。
  • 换算只用 float 单精度（10 MHz 频率下 ticks/µs = 10.0 精确；ticks/(freq/1e6) 在 float 精度内对 ms 级间隔足够）。没有 100 ns 单位，最小实用单位是 µs，超过 2^24 tick（约 1.7 s @10MHz）后 float 的有效位开始丢精度。推导
  • tick 溢出：QPC 是 64 位计数器不会在进程寿命内回绕，所以 FUN_140043990 不做回绕处理；FUN_140043050 只做了 float 转 int64 的 2^63 溢出补偿（fVar2 = 9.223372e18 …），属于编译器生成的 (long long)(float) 边界代码。

8. 对 OpenScope 的启示

  1. 抄：单工作线程 + 32 槽命令环 + id→处理器表 + 完成回调自销毁。 OpenScope 的设备动作（开始/暂停/停止采集、解析 ELF、上传/下载变量表、保存工程、检查 ELF 变更）与这套 id 表几乎是 1:1。收益：串行化免费获得（一个 worker，任意两个设备操作不会并发）、生命周期简单（作业由 worker 自释放，创建者不关心谁管内存）、UI 只投递不等待。注意补上 SEGGER 的缺陷：队列满时不要无限等（加"队列满即失败"或可增长队列），并给作业加真实撤销（SEGGER 的"取消/超时"是假的——作业照样执行）。
  1. 抄：所有跨线程 UI 更新走"锁内写状态 + emit 队列信号"。 OpenScope 是 C11 + 自绘/Qt，无论哪种，'worker 只写状态结构 + 用一次 PostMessage/信号唤起 UI，UI 线程读同一结构渲染' 这条纪律都值得照搬；绝不要让 worker 直接碰控件。SEGGER 还额外做了两件值得学的事：
  2. 反向"worker 阻塞等 UI"（进度条 FUN_14004e1f0：建事件 → 发信号 → WaitForSingleObject → 关闭句柄），让长任务能显示进度又不用回调套回调；
  3. 退出时的确定性握手（DAT_14286d37c 状态机 + 退出作业 + 事件等待 + 逐级 CloseHandle），避免"关窗后 worker 还在跑"。
  1. 抄：可开关的带守卫堆（标签 + 0xDEADBEEF + 32 字节尾哨兵）。 增量成本仅 0x40 字节/块、payload 仍 16 字节对齐、free 时逐字节验哨兵并弹诊断信息；标签字符串在"多缓冲区 + 多线程"的项目里是定位泄漏/越界最快的线索。OpenScope 已有 JLink 块读/写与多缓冲（HSS/RTT/网络镜像），建议默认开启守卫模式（SEGGER 默认关闭，等于白写），并把 free 时校验改成"每次释放都校验 + 记录首个越界块的 tag"。
  1. 抄：日志的"段嵌套 + 深度即级别 + 段末汇总弹窗"。 log_section_begin("Parse ELF") → 期间 ERROR/WARNING/INFO 累积到内存缓冲并计数 → log_section_end() 时"有错弹错误框 / 无错但有输出弹信息框"（级别由注册表 LogLevel 控制在多深还打）。这比"每个错误一个 MessageBox"体验好得多，也天然产生可复制的操作日志（OpenScope 的 request.md 驱动开发流程 + 网络 E2E 脚本正好需要这个：一次自动化操作导出一段日志文本）。
  1. 抄：双时钟分工（QPC→µs 用于测量、winmm ms 用于调度）+ 首调用捕获基准。 FUN_140043990/970/050 这三层（相对 tick / 相对 µs / 频率换算一次性缓存）干净且便宜，OpenScope 的采样率统计、超时、进度都该用它；但别学 SEGGER 的 timeGetTime 做周期调度（15.6 ms 分辨率 + 加载了 timeBeginPeriod 却不用）——OpenScope 要么 timeBeginPeriod(1)，要么直接用 QPC 做等待计算并 Sleep 到目标时刻。
  1. 别抄：
  2. 用全局单例 + 一把大锁串起"应用状态"（MainWindow+0x318 保护几十个字段、DAT_14285d420 RTT 状态 0x5bc 字节全局）。OpenScope 的 net_drive（多实例、跨机）会直接撞车——应按"实例/会话"对象化，锁粒度按对象而不是全局。
  3. 把"栈上描述符"塞进跨线程队列（id 15 的停机作业）；OpenScope 里一旦有超时/重试就会踩悬垂指针。
  4. _guard_check_icall(DAT_14286d388, msg) 式的"全局对象指针当函数指针调"写法，以及 MessageBoxA 与 Qt 弹窗混用（OOM 时弹出 Win32 框，可能在非 UI 线程）。
  5. 用样本索引当时间轴（DAT_14285da80 + DAT_14285da78）而不记录时间戳——多速率/多实例合并数据时会很难对齐（OpenScope 的 ELF 变量 + 网络远端数据尤其明显）。
