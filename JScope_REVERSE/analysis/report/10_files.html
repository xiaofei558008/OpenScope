10文件格式与数据导出

J-Scope 只碰四类文件：工程 .jscope(XML)、设置 JScopeSettings.ini、 ELF、以及数据导出（CSV 文本 与 JRAW 无头二进制）。 采集过程不落盘——全二进制里只有三处数据文件 I/O（CSV 写、JRAW 写、JRAW 读）。

10.1 工程文件 .jscope（XML）观测

<JScopeProject>
  <FileVersion major=".." minor=".."/>
  <Project>
    <Configuration>
      <Connection> <TargetInterface/> <InterfaceSpeed/> <SerialNo/> <Nickname/>
                   <JTAG_IRPre/> <JTAG_DRPre/> <ScriptFile/> </Connection>
      <TimeResolutionUs/>  <SamplingPeriod/>
      <IsRTTSession/> <IsRTTWithTimeStamp/> <IsRTTPlus/>
      <ElfFile/> <JLink/> <Scope/> <DataFile/> <RawFile/> <Timestamp/>
      <Trigger> <Level/> <Auto/> <Rise/> <Fall/> </Trigger>
    </Configuration>
    <SelectedSymbols>
      <Symbol> <Options Name= Type= Size= Address= TypeID= GraphColorRed= GraphColorGreen=
                 GraphColorBlue= YMinSampled= YMaxSampled= YAvgSampled= Offset= ShowInGraph=
                 YOffset= IsAutoConfig= YResolution= MaxValue= File= DrawStyle=
                 NameWithParents=/> </Symbol>
    </SelectedSymbols>
  </Project>
</JScopeProject>
  • 读取强依赖层次：JScopeProject → FileVersion → Project → Configuration/SelectedSymbols，缺一层即失败。
  • 读取方是"项目结构"（基址比运行期 Configuration 高 8 字节，见 §9.3）；写入方 FUN_140046110 全部走同一套属性名。
  • <DataFile> / <RawFile> 只是"上次导出到哪"的路径记忆（对应 cfg+0x184 / cfg+0x288），不是自动记录文件。
  • 工程里保存 YMinSampled/YMaxSampled/YAvgSampled/Offset/MaxValue 等运行期统计量—— 也就是说 J-Scope 会把"上次看到的曲线范围"一起存下来，再打开时波形直接落在熟悉的量程上。

修正上一版报告的一处误判："File too large - maximum file size (%d bytes) exceeded!" 不是数据导出的限制，而是 INI 读取器的上限：JScopeSettings.ini 超过 30,000 字节即拒绝解析（FUN_14004f590 中 0x7531 判据）。

10.3 CSV 导出（File → Export Data… / Ctrl+D）观测

FUN_140047390（同步执行，不走作业队列）

fopen_s(&fp, path, "w");                        // 文本模式 → "\n" 落盘为 CRLF；★ 无 BOM
fputs("Timestamp", fp);
for (n = varList; n; n = n->next) { fputs(";", fp); fputs(*(char**)(*n + 0x108), fp); }
fputs("\n", fp);                                    // ★ 分隔符是"分号"，虽然扩展名叫 .csv

for (i = 0; i < writeIdx - 1; i++) {                 // ★ 物理下标，不做环形重映射
    fprintf(fp, "%u", tsRing[i]);                    // 时间戳：无分隔符前缀
    for (n = varList; n; n = n->next) {
        switch (v->TypeID) {
          case 1: case 2: fprintf(fp, ";%f", (double)val);   // 浮点 6 位小数
          case 5: case 6: case 7: case 8: case 10: case 11: case 12:
                   fprintf(fp, ";%i", val);                  // ★ 有符号打印，uint32 > 2^31 会显示为负数
          default: /* TypeID 3/4/9/13 → 整列静默不输出，行内直接少一段 */
        }
    }
    fputs("\n", fp);
}

一行的样子：123456;0.500000;-3;42。小数点固定为 .（程序全程未调用 setlocale）。

两个真实缺陷（照抄必翻车）：

① writeIdx == 0 时 writeIdx-1 下溢成 0xFFFFFFFF， 循环跑 42.9 亿次并越界读环——即"缓冲刚清零就导出"会卡死/崩溃。 ② 环绕回后按物理下标导出，得到的是"绕回点之后写的那批"，而不是时间上最老的样本； 最新的那个样本永远不导出（上界是 writeIdx-1）。

10.4 JRAW 导出（File → Export Raw… / Ctrl+R）观测

.jraw = 无头裸样本流（★ 无魔数 / 无版本 / 无变量名 / 无对齐）

+0x00timestamp_usuint32 LE
+0x04var0var0.size 字节
…var1var1.size
…varNvarN.size
ts (µs, LE) var0 var1 varN → 样本长度 = 4 + Σ(变量 size)，等价于 HSS 的样本流
项值
变量顺序变量链表的挂接顺序 = UI 变量树顺序 = HSS 描述符顺序（不是按地址排序）
样本数lastIdx；已绕回时为 0x800000（整环，逻辑下标，时间递增）
打开方式fopen_s(..., "wb")（二进制，不做 CRLF 转换）；写失败只检查 fp，无磁盘满分支
格式说明文件里没有；只在导出完成后弹一个 OK 框，把 "Raw data exported in the order:\nTimestamp\n<变量名>…" 念给用户

一句话记住 JRAW：它就是"探针给主机的样本流"原样落盘。 因此同一份 .jscope 工程 + 同一组变量顺序是解释它的唯一钥匙——文件离开工程即不可读。

10.5 JRAW 导入（File → Import Raw / Ctrl+T）

FUN_14004cf60（对话框 "Open JRAW file" / 过滤器 "JRAW (*.jraw)"）→ 作业 APP: <ImportRaw> → FUN_140046e80

sampleSize = 4 + Σ(v->size);                     // 与导出同一算法
fopen_s(&fp, path, "rb");  fileSize = ftell(...);
if (fileSize % sampleSize != 0)                 // ★ 唯一的"格式校验"——提示后继续，尾部余数丢弃
    MsgBox("File size does not align with selected symbols!…");
if (nSym * 0x4000000 + 0x2000000 < fileSize)       // 容量上限 = 变量数×64 MB + 32 MB
    MsgBox("File size exceeds symbol buffers!\n Excess data will be discarded.");
p = malloc(fileSize);  fread(p, 1, fileSize, fp);
ImportIntoRings(fileSize - fileSize % sampleSize, p);   // FUN_14004ded0（持锁）

// FUN_14003de60 —— 清环 + 临时强制"有时间戳" + 复用实时解包器
memset(tsRing, 0, 0x2000000);              // 32 MB
FUN_14003e050();                              // 每变量 64 MB 环 malloc + memset
FUN_140040980();                              // writeIdx/wrapped/lastIdx = 0，通知 UI
savedTsFlag = IsRTTWithTimeStamp;  IsRTTWithTimeStamp = 1;   // ★ 强制走"用文件里的时间戳"分支
FUN_140042a60();                              // 重算 v->sampleOffset
UnpackSamples(nBytes, data);                  // ★ 与实时采样同一个解包器
IsRTTWithTimeStamp = savedTsFlag;

结论：导入 = 把离线文件当作一段 HSS 采样灌进同一套双环。因此导入后的数据在 触发判定、统计量、绘图、再次导出等所有环节与实时数据完全同构，零特判代码。

回答"导出 .jraw / 导入 *.raw 是不是同一种格式"：是。 导入对话框实际用的过滤器就是 JRAW (*.jraw)；Binary file (*.raw) 与 Import Raw 两条字符串只存在于 .rdata 的一张扩展名表里， 没有任何代码引用（见 §17 未知点）。
