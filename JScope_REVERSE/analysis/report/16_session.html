12. 对 OpenScope 的启示

  1. 命令行只做"薄壳"，两阶段解析值得抄。 J-Scope 把 -openprj 单独放在阶段 2 先"探明"，再在阶段 1 才真正执行；-USB/-IP 的"必须与 -openprj 同用"就靠阶段 2 留下的一个布尔标志实现，没有额外的校验框架。 OpenScope 若要加网络/多探针参数，照这个模式只需一张 {串, 掩码, 处理函数} 表 + 一个 for 循环（FUN_140041cd0 全文不到 100 行 C）。注意 J-Scope 用的是前缀匹配（strncmp(arg, name, strlen(name))），这会让 -openprjX 也命中，重实现时建议改成整串匹配。
  1. 后端 DLL 的三级查找 + 按名解析是可直接复用的模板，但要修正一处认知。 实际顺序是 exe 同目录 → 另一模块目录 → 注册表 SEGGER\J-Link\InstallPath（再 bin_x64\）→ 注册表 SEGGER\Flasher，而不是"先交给系统搜索路径"。HKCU 先于 HKLM。 29 个 API 全部惰性解析 + 失败给 MessageBox + exit(1)，语义干净。OpenScope 若同时支持 J-Link/ST-Link，建议照此抽象，但把 exit(1) 换成可恢复错误（J-Scope 一旦找不到 DLL 就直接杀进程）。
  1. 设置持久化：J-Scope 的实现有明确缺陷，别照抄。 ① JScopeSettings.ini 与 exe 同目录（Program Files 下通常无写权限，且多进程会互相覆盖）；② 整个文件用一个 30000 字节定长缓冲读改写，超过就拒绝启动读取；③ 每次改一个键都整文件重写。 OpenScope 应改为 %APPDATA% 下的 QSettings/JSON，并做"读-改-写+文件锁"，MRU 也放一起而不是拆到注册表（J-Scope 的 MRU 在 HKCU\Software\SEGGER\J-Scope\Recent File List 1\，键名 File1..File10，1 基）。
  1. LogLevel 其实不是"严重性等级"，而是"缩进深度阈值"。 FUN_140041570(level) 就是 level <= LogLevel || LogLevel == 9，而调用方传的 level 全部形如 depth*2±1。值域 1..9、默认 3。 OpenScope 若要分级日志，建议分开两个概念：严重性（Error/Warn/Info/Debug）+ 深度阈值，别学 J-Scope 把两者压进一个整数。
