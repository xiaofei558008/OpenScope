HSS 能力探测与时间基

if (mode == HSS) {
    if (!JLINKARM_EMU_HasCapEx(0x35)) {          // 0x35 = HSS 能力位
        period_us = 20000;                        // 回退 20 ms 轮询
    } else {
        if (JLINKARM_GetDLLVersion() > 0xc79b) {   // DLL 版本门限 [推断]
            JLINK_HSS_GetCaps(&caps);
            TimeResUs = 1000000 / caps.field_at_4;
        } else {
            period_us = 10;
        }
    }
}

推断 caps.field_at_4 应为 HSS 时间戳频率（Hz）， 故 1e6 / freq = µs/tick。若它是「ns/tick」，此式量纲不符。 这是重实现时最需要实测确认的一处。

重要修正 观测 —— 该全局（_DAT_14285da90）经 Ghidra 全量交叉引用确认 只有 2 处写入、0 处读取（写入点：caps 换算、以及一个纯 setter FUN_14003f400）。即：

· 本版本中「时间分辨率」是写后即弃的残留状态；
· 更关键的是 —— 样本里的时间戳是原样存储的 （FUN_14003ff40 直接 tsRing[i] = sample[0]，无任何缩放）。

结论：HSS 探针给出的时间戳本身就是 µs，主机侧无需换算。 这大幅简化了 OpenScope 的重实现。

05HSS 高速采样协议（异步）

5.1 变量描述符数组

FUN_140041f30 构造并下发给探针。

// 每个变量 16 字节；末尾追加一个 {addr=0,size=0} 终止项
struct HssVar {          // 16 bytes
    uint32_t addr;       // +0x00  变量绝对地址
    uint32_t size;       // +0x04  字节数
    uint32_t reserved0;  // +0x08  = 0
    uint32_t reserved1;  // +0x0C  = 0
};

uint32_t n = 0;
HssVar *list = malloc((n + 1) * 16);   // +1 给终止项
memset(list, 0, (n+1) * 16);

uint32_t off = 4;                    // ★ 从 4 开始：前 4 字节是时间戳
for (每个被选中的变量 v) {
    v->sampleOffset = off;           // 记在 v+0x38C
    off += v->size;                  // v+0x31C
    list[i].addr = v->addr;          // v+0x318
    list[i].size = v->size;
    /* 同时复位统计量：
       v->yMaxSampled(+0x398) = -DBL_MAX   (0xFFEFFFFFFFFFFFFF)
       v->yMinSampled(+0x3A0) = +DBL_MAX   (0x7FEFFFFFFFFFFFFF)
       v->writePtr(+0x3C8) = v->dataBuf(+0x3D0) = 0   */
}
list[n].size = 0;                    // 终止项

rc = JLINK_HSS_Start(list, n, samplingPeriod_us /*config+0x5A8*/, 1 /*flags*/);

5.2 采样包格式

JLINK_HSS_Read(buf, size) 返回本次读到的字节数， 缓冲区内容为紧密排列的定长样本。变量在样本内的偏移在 JLINK_HSS_Start 之前就固定算好，读取后直接按偏移切片。

实例：3 个变量 g_speed(float32) · g_state(uint8) · g_count(int16) → 样本 = 4+4+1+2 = 11 字节

offset 0timestampuint32 · µs
offset 4g_speedfloat32 · 4 B
offset 8g_stateuint8 · 1 B
offset 9g_countint16 · 2 B
ts (µs) g_speed g_state g_count → 样本按此长度首尾相接填满整个读缓冲

5.3 读取泵

FUN_140040fa0

int bufSize = 0x200000 - (0x200000 % (sampleSize * numVars));  // ≈2 MB 对齐
void *buf = malloc(bufSize);
int n = JLINK_HSS_Read(buf, bufSize);      // 返回字节数
if (n >= 0) UnpackSamples(n, buf);
free(buf);

由 10 ms 周期 Job（APP: <ReadPeriodic>，job->period = 10）驱动 —— 探针在后台以设定周期自主采样并缓存，主机每 10 ms 批量取走积压数据。 采样率与主机轮询频率彻底解耦，这正是 HSS 能到 µs 级的原因。

06双环数据模型

这是 J-Scope 高性能绘图的核心设计。两个环都是 8,388,608 样本 深，索引取模 0x7FFFFF。

时间戳环 静态 · 8,388,608 × uint32 = 32 MB
tsRing[i] = sample[0] · 写指针 DAT_14285da80，绕回标志 DAT_14285da78
每变量数据环 堆 · 8,388,608 × 8 B = 64 MB / 变量
memcpy(v->dataBuf + idx*8, sample + v->sampleOffset, v->size)
分配处 memset(v->dataBuf, 0, 0x4000000)。 无论变量是 1/2/4/8 字节，都占 8 字节槽位 —— 用内存换 O(1) 均匀索引。

时间戳语义

函数 FUN_14003ff40 —— 三种模式分支：

if (mode == HSS)            tsRing[i] = sample[0];      // 探针给的 µs
else if (rttWithTimestamp)  tsRing[i] = sample[0];      // 目标给的 µs
else {                      // RTT 无时间戳 → 合成 100 µs 均匀栅格
    if (i != 0)         tsRing[i] = tsRing[last] + 100;
    else if (wrapped)  tsRing[0] = tsRing[last] + 100;
    else              tsRing[0] = 0;              // 首个样本 t=0
}

与二进制中告警串逐字吻合：

RTT channel is set up to provide no timestamp!
Without timestamp J-Scope will assume that data points are uniformly
distributed with a gap of 100 [us] each.

样本解包与采样率

FUN_14003fa70 —— HSS 与 RTT 共用

numSamples = nBytes / sampleSize;              // DAT_14085d1ec
for (每个样本) {
    StoreTimestamp(p);                          // 写时间戳环
    for (每个变量 v) {
        StoreVarSample(v, p);                   // memcpy 到 v 的环
        /* 触发判定 FUN_1400415a0(...) → 0/1/2/3；命中则 FUN_140042ac0(v) */
    }
    p += sampleSize;
    writeIdx = (writeIdx + 1) & 0x7FFFFF;
}

FUN_140041710 尾部 —— 状态栏速率

elapsed = timer_ticks();                                  // 100 ns 单位 [推断]
samplesPerSec = (uint)(numSamples * 10000000 / elapsed);

对应 UI 字符串 kSamples/s、Samples/s、FPS: 、Buffer: 。

代价与启示 —— 4 变量 = 256 MB，8 变量 = 512 MB。 OpenScope 若要做长时间记录，应改为按类型宽度紧凑存储（1/2/4/8 B），或分段 / 落盘。 这是 J-Scope 一个明显的可优化点。

7.2 VarFormat 编码 —— 本次逆向的关键成果

上行通道名形如 JScope_<VarFormat>， 其中 VarFormat 是「类型字符 + 尺寸数字」严格成对的串： 

JScope_t4i4f4     →  时间戳 + int32 + float32
JScope_u2i2u4     →  uint16 + int16 + uint32
JScope_t4f4f4f4   →  时间戳 + 3 个 float32

解析逻辑（FUN_14003fc90）：跳过首个 _ 之前的内容，之后每次固定取 2 个字符（含 t，它同样消耗一位）。

类型字符尺寸数字TypeID含义
t（占位，值忽略）—时间戳标志（置 IsRTTWithTimeStamp）
b15bool
f41float32
f82float64
u1 / 2 / 4 / 86 / 7 / 8 / 9uint8 / 16 / 32 / 64
i1 / 2 / 4 / 810 / 11 / 12 / 13int8 / 16 / 32 / 64
其它——忽略

解析出的类型用于 AddSymbolFromFormat(size, typeID, 0, desc)，描述串即二进制中的：

"%d Byte bool RTT Data %d"      "%d Byte float RTT Data %d"
"%d Byte unsigned RTT Data %d"  "%d Byte signed RTT Data %d"

失败路径的两条原文：

No RTT Up-Channel named "JScope_%Format%" found
The first RTT Channel named JScope_... found did not contain a valid VarFormat

注意 —— RTT-VarFormat 模式下目标端无需 ELF：通道名自带完整布局。 这是与 HSS 模式的本质差异。

7.3 跨读取的样本拼接

RTT 无「整样本」保证，读取会在样本中间截断。J-Scope 用 ≤64 字节的残留缓冲拼接跨读取的半个样本（FUN_140042260）： 

if (targetErrorPending()) { partialLen = 0; /* 清状态 */ }
else partialLen = carryLen;                       // 上次残留

memcpy(buf, carry, partialLen);                    // 先补上残留
n = JLINK_RTTERMINAL_Read(ch, buf + partialLen,
                          min(readBufSize, 0x200000) - partialLen);

total     = n + partialLen;
remainder = total % sampleSize;
UnpackSamples(total - remainder, buf);             // 只解完整样本
if (remainder == 0) carryLen = 0;
else { carryLen = min(remainder, 0x40);             // ★ 上限 64 字节
       memcpy(carry, buf + (total - remainder), carryLen); }

RTT 读缓冲：readBufSize = min(0x2000, channelBufSize)，分配标签 "RTT read buffer allocation"。

7.4 控制通道

FUN_140040ed0 —— 最多 101 次重试

循环最多 101 次：
    n = JLINK_RTTERMINAL_Read(ch, tmp, 256)
    累计满 256 字节 →
        若 tmp[0] != 0 → 报 "Target Error: %s" 并返回失败
        否则返回成功
    Sleep(1)
超时 → 返回 0xFFFFFFFE

架构亮点 —— HSS 与 RTT 共用同一个 UnpackSamples （FUN_14003fa70）：上层数据模型完全统一，只有「字节从哪来」不同。 这是非常干净的抽象。

SuppressGUI = 1/0 会作为 ExecCommand 下发。

12对 OpenScope 的启示

12.1 三条最有价值的结论

  1. HSS 是 OpenScope 高速采样的现成答案。 JLINK_HSS_Start(变量表, 数量, 周期µs, 1) + 周期 JLINK_HSS_Read 到 2 MB 缓冲。 探针自主按周期采样并缓存、带 µs 时间戳、主机批量取走 —— 采样率与 USB 往返解耦。 这正对应 request.md 第 15 条「第二步：真 µs 采样（片上缓冲，XCP 式）」， 且不需要在 MCU 上跑采样代码（HSS 走 AHB-AP 后台访问，不占用 DWT/SWO）。
    注意：HSS 属 J-Link SDK 功能，无公开文档；§05 是可直接使用的调用契约。
  2. HSS 与 RTT 可以共用同一数据模型。 J-Scope 把两者的字节流都喂给同一个 UnpackSamples， 统一成「定长样本 + 首 4 字节 µs 时间戳」。 OpenScope 的网络模块（request.md 第 14 条）应当照搬这个抽象： 采集后端只负责产出「带时间戳的定长样本流」，压缩 / 传输 / 绘图全部复用。 这也直接解决「本地 ST-Link/J-Link 采集 → 网络传给远端」的接口设计。
  3. RTT VarFormat 让目标端零 ELF 依赖。 通道名 JScope_t4i4f4 自带完整布局。OpenScope 若要在网络对端（无 ELF）显示波形， 这是最省事的方案 —— 发送方把变量布局编码进通道名 / 握手包即可。

12.2 建议抄 / 不抄

项建议理由
运行时按名解析后端 DLL抄已在 OpenScope 网络模块验证过的模式；同时兼容 J-Link / ST-Link
双环数据模型（时间戳环 + 每变量环）抄，改进索引 O(1)、绘图简单；但 8 B/样本固定槽位太浪费
8,388,608 样本固定深度不抄应改为可配置深度或分段落盘（OpenScope 已有历史回传需求）
每变量 64 MB 预分配不抄8 变量即 512 MB；应按类型宽度紧凑存储（1/2/4/8 B）
时间戳统一为 µs、uint32抄与 J-Scope 对齐便于互操作；注意 2³² µs ≈ 71.6 分钟后回绕
无时间戳时合成 100 µs 栅格抄低成本兜底，避免绘图断链
RTT 跨读取 ≤64 B 残留拼接抄流式协议必备；比「丢弃半样本」健壮得多
10 ms 采样泵 + 2 MB 批读抄让探针 / 目标做缓冲，主机不与采样率耦合
带守卫的自研堆分配器可选调试期价值高（能抓越界 / 野指针），发布期有开销
JLINKARM_DEVICE_SelectDialog 选型弹窗不抄与 request.md 第 17 / 21 条「不要弹窗选芯片」直接冲突

12.3 已知坑

  • JLINK_HSS_Start 第 4 参数为 1（flags）观测，语义未知。
  • caps.field_at_4 的单位需实测确认（§04 末）。
  • TypeID 3/4 语义未确证（§08）。
  • -USB / -IP 选项必须与 -openprj 同用，否则报错 —— 因连接参数来自工程文件。
  • RTT 模式强制要求指定目标器件：In RTT mode specifying the target device is mandatory.
